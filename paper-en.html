Grid shape as an independent lever in 2–4-bit weight-only LLM quantization
fitting non-uniform grids from the weight distribution and the Hessian

Roman S. Pokora · Independent researcher · Preprint, November 2026

Abstract

We study how the placement of quantization levels affects 2–4-bit weight-only quantization of large language models. At equal bit width, a grid fitted to the weight distribution and to channel saliency lowers perplexity more than the choice between uniform and fixed non-uniform alphabets. For each weight tensor we fit a 2b-level lookup table with a four-parameter Kumaraswamy quantile function (one pair per half-distribution), optimized by compass search on a Hessian-diagonal-weighted squared error. The table costs 32 fp16 bytes per tensor, fitting takes under a second on CPU, and the decoder is unchanged. The procedure is deterministic: with the histogram objective the grid is an exact function of the tensor, with no random subsampling, training, or gradient computation. It changes the alphabet rather than the rounding rule, so it composes with GPTQ, rotation-based preconditioning, sparse corrections, and mixed-precision allocation. On SmolLM-135M and Qwen2.5-0.5B (WikiText-2, activation-based calibration, float64 GPTQ) the fitted grid lowers perplexity at equal width: 7–15 % over uniform at 4 bits (Qwen: 22.65 → 19.23) and up to three orders of magnitude at 3 bits (Qwen: 55.703 → 68.5; SmolLM: 1.580 → 52.6). Equal-mass grids are 31–331 % worse than uniform, consistent with the Zador–Gersho p1/3 level-density law. Fixed NF4 and FP4 E2M1 grids lose to fitted ones. The method rests on classical Lloyd–Max quantization theory; the contribution is a cheap parametric fit. Results cover two small models and one corpus; larger models, broader benchmarks, and kernel optimization remain open.

Keywords: weight quantization, large language models, GPTQ, non-uniform grids, Kumaraswamy distribution, Lloyd–Max algorithm, deterministic quantization, perplexity.

1. Introduction

Weight quantization of large language models (LLMs) has become the primary way to reduce inference memory requirements: weights occupy a volume proportional to the number of parameters and do not depend on the context length. The working standard is the weight-only mode: weights are represented by low-bit-width integer codes (3–4 bits) with a scale per group of 64–128 weights, while activations stay in fp16. In this mode, quality is determined by which values the weights are encoded with, and hardly depends on these codes being "integers".

Traditionally, the value grid is chosen uniform-representative: after subtracting the zero point, weights are normalized by the group maximum and rounded onto a uniform lattice (the NF4 variant from QLoRA [3] takes a fixed Gaussian grid). Meanwhile, the transformer weight distribution is sharply peaked, with heavy tails and strong channel anisotropy; a mere exponent shift of the group scale does not cope with this. In this paper we test the hypothesis that the grid shape — the placement of levels relative to the weight density — is an independent quality lever, comparable in effect to the rounding algorithm.

We call the method SHAPEQ (shape-adaptive quantization). For each weight tensor we fit a table of 2b levels (for 4 bits — 16 numbers stored as 32 fp16 bytes per tensor), generated by the quantile function of the Kumaraswamy distribution [10] with four parameters (one (a, b) pair for the positive and negative halves). The parameters are fitted by compass search on a weighted objective in which each weight's error contribution is weighted by the Hessian diagonal of the loss — that is, what is optimized is not the "average distance to a weight", but a proxy for the model's actual degradation. Rounding is performed by GPTQ [1] with the unchanged uniform code: grid shape and smart rounding add up.

The approach is conservative by design. It relies on scalar quantization theory that has been established for decades [8, 9, 16] and adds only a parametric description of the level density. No model training, no gradient computation, and no search over the full tensor are involved: the fit is a coordinate descent over four numbers on a one-dimensional objective. With the histogram implementation (Section 7.7) the grid is an exact function of the tensor, so the same checkpoint always produces the same table. Because the method changes only the alphabet, it is orthogonal to the rest of the quantization pipeline: GPTQ and AWQ rounding, rotation-based preconditioning, sparse corrections, and mixed-precision bit allocation can all use the fitted grid unchanged. We test the combination with GPTQ here; the other combinations are discussed in Section 7.4.

Contributions of this work:

  1. a formulation of grid fitting as a weighted Lloyd–Max quantization problem with a parametric family of shapes (Section 4), and a practical fitting algorithm costing under a second per tensor (Algorithm 1);
  2. an experimental "layer-MSE → perplexity" protocol on two models (SmolLM-135M, Qwen2.5-0.5B) and the full bit-width ladder 8/6/4/3/2 for the fitted grid (Section 6);
  3. an experimental refutation of the popular "equal-mass" grid idea (Section 6.5) and a quantitative assessment of the contribution of Hessian weighting, symmetry, and the number of shape parameters (Sections 6.2–6.4);
  4. a comparison with fixed "smart" grids — NF4 [3] and the hardware FP4 E2M1 from the OCP MX format [14]: per-tensor shape fitting gives a stable −15…−17 % of weighted error relative to NF4; the FP4 comparison is included in the protocol (Section 6.6).

2. Related work

Optimal grids. The problem of choosing levels that minimize the mean squared deviation for a given density is classical: Lloyd's necessary conditions (1957 [8]) and Max's independent solution (1960 [9]) yield an iterative "centroids–nearest regions" algorithm — what is known in machine learning as Lloyd–Max / k-means for 1D; for a large number of levels, the optimal level placement becomes asymptotically quantile. NF4 from QLoRA [3] uses this idea in "frozen" form — quantiles of the normal density without fitting to the data. We use a parametric family instead of Lloyd iterations, because (a) our objective is Hessian-weighted and includes the GPTQ stage, for which there are no reference "centroids", and (b) a cheap online procedure per tensor is required.

Rounding algorithms. OBS/GPTQ [1] minimize the quadratic form tr(ΔW H ΔWᵀ) with the Hessian from calibration activations; AWQ [2] protects "important" channels by scaling; sparse hybrids (SpQR [6], SqueezeLLM [4]) move outliers into sparse corrections — effectively adding more bits to the model, but locally. Our method is orthogonal to this entire list: it changes the alphabet, not the rounding order, and in this paper it is combined only with GPTQ.

Fixed microformats. The OCP Microscaling family (MXFP8/MXFP4, [14]) standardizes block formats with e4m3/e8m0 scales and a fixed E2M1 grid for 4 bits; GGUF/IQ4_NL in llama.cpp [15] is the de facto standard of a "fixed non-uniform" grid in production CPU inference. These formats choose the grid once for "average weights"; we show that per-tensor fitting is cheap and consistently outperforms them at equal storage cost.

3. Problem statement

Let W ∈ ℝm×n be the weight tensor of a linear layer, X — the calibration activations (T × n), H = XᵀX/T — their Gram (approximate Hessian) matrix. Second-order loss degradation of a layer is estimated as tr(ΔW H ΔWᵀ) [1]; we use its diagonally corrected version at the grid-fitting stage (weights wi = diag(H), with smoothing and a correction for GPTQ error propagation), and the full quadratic form — at the rounding stage.

minG, idx Σi,j diag(H)j · (Wij − s · Gidx(i,j))²,

where G is a table of L = 2b levels (shared across the tensor), s is the group scale (fp16 per 128/96 weights), idx are integer codes. Storage: b bit/weight + 16 bits per group + 32 bytes of LUT per tensor (16×fp16) — on an 896×4864 tensor this is 0.0006 bit/weight, i.e. free for any b ≤ 8.

4. Algorithms

4.1. Family of shapes

As the quantile function (mapping the uniform grid uk = (k+0.5)/L to the "magnitudes" of the levels) we adopt the Kumaraswamy inverse distribution function [10]:

Q(u; a, b) = ( 1 − (1 − u)1/b )1/a,

which for a = b = 1 yields a uniform grid, for a, b > 1 an S-shaped one (densification toward the modal zones and rarefaction in the tails), for a, b < 1 a reverse-S one (densification toward both poles). With one pair (a, b) per half of the distribution, the shape is described by four numbers; this family covers all bend types observed in the weight histograms of 21 SmolLM layers (Section 6.4). The negative and positive halves are built independently and joined at zero; the zero level is always present in the table.

4.2. Hessian-guided grid fitting (Algorithm 1)

Input: W (m×n), h = diag(H) with smoothing h ← (h + ε·mean h)/(1+ε),
      L, group g.
1  For each group, weights are normalized by absmax → y ∈ [−1, 1];
   magnitudes |y| with weights w = repeated h form the sample (≤150 000 points).
2  θ = (a₋, b₋, a₊, b₊) ← (1, 1, 1, 1)   // uniform as the starting point
   step d ← 0.5
   while d > 0.02:
     for each of the 8 compass directions:
       θ' ← θ ± d·eᵢ (probes ≥ 0.05 only)
       θ ← argmin C(θ'), where C is the objective of Alg. 2 with L levels
     d ← d/2
3  κ ← scale search (Alg. 2, item 4): shift the whole table by a factor κ
   on a 0.90…1.10 grid, minimizing the same objective   // "tail" trade-off
4  G ← shapeq_grid(L, θ) · κ, normalize by the absmax of the table.

The objective is the normalized weighted MSE Σ w·(y − G[idx(y)])² / Σ w·y², computed over 150 thousand subsample points in ~1 ms; a full compass descent (≈60 objective evaluations per side) costs < 1 s per tensor. Weighting by diag(H) is what makes the method "Hessian-aware": channels with large activations get denser levels. The ε smoothing guards against zero weights; without it the fitting degenerates.

4.3. Table refit (Algorithm 2, "Hessian Lloyd")

Input: W, h, G (after Alg. 1), number of rounds R (we use R = 3).
repeat R times:
  1  idx ← nearest level (in the group scale);
  2  for each level k: Gₖ ← Σ w·y / Σ w over all points of bucket k
     (weighted centroid; empty buckets are not moved);
  3  renormalize G by absmax;
return the best G under the objective C.

This is the classic Lloyd step with Hessian weights: it does not change the shape family; it "polishes" the levels to optimal for the real data shape and the real bucket partition. The refit is cheap (one pass over the tensor per round) and was used in our experiments as a booster for the winner (the "+refit3" configurations).

4.4. GPTQ rounding (Algorithm 3)

We use the reference GPTQ implementation [1] with the diagonal correction: cholesky of H⁻¹, sequential column-by-column rounding with error propagation to unprocessed columns. The only change relative to the canon is that the level weighting grid is not uniform but G from Algorithm 1 (for fixed grids — NF4/FP4 — its own table with no fitting). Numerical operations run in float64 on CPU; this matters: f32 GPTQ variants on GPU give a discrepancy of order 10⁻² from f64 at rare level boundaries (Section 5.4).

4.5. Storage and cost

A weight tensor after quantization: codes (b bit/weight) + group scales (fp16 per 128 Qwen / 96 SmolLM weights = 0.125–0.167 bit/weight) + a 16×fp16 LUT = 32 bytes per tensor + 4 bytes of group zero point (absorbed into the scale). The final cost for our runs is the "bit/weight" column of Tables 1–2: 3.25 and 4.25 bits. Decoding at inference is a table lookup (as IQ4_NL in llama.cpp [15]), latency O(1); matrix multiplication remains weight-only (activations fp16), so 4-bit hardware FP4 matrices [14] do not compete with our method but complement it (Section 7.4).

5. Experimental protocol

5.1. Models and data

SmolLM-135M [13] (30 layers, hidden 576, llama-type architecture) and Qwen2.5-0.5B [12] (24 layers, hidden 896, GQA with 2 kv heads). Calibration: 2048 (SmolLM) / 1024 (Qwen) sequences of 512 tokens from WikiText-2 [11]; evaluation — the same chunks (96 / 64 sequences with a sliding window, without overlap), perplexity over all tokens. Groups: 96 and 128 weights. All linear layers (q/k/v/o, gate/up/down) are quantized simultaneously, embeddings and layernorms remain fp16/fp32 — the standard weight-only scheme.

5.2. Two-level metric

First the cheap proxy — relative layer error tr(ΔW H ΔWᵀ)/tr(W H Wᵀ) over 21 sampled layers (runtime < 1 min per configuration), then full perplexity (10–90 min per configuration). The proxy was used to cull shapes that were clearly doomed (Section 6.5); final conclusions rest on ppl only.

5.3. Fairness of comparisons

All configurations in one comparison row use the same Hessian (shared calibration), the same GPTQ code, and the same evaluation chunks. A known simplification: the Hessian is computed once for the fp16 model and is not rebuilt after quantization ("stale Hessian" — standard GPTQ practice [1]); for severely degraded configurations (b2/b3 uniform) this may underestimate the real damage — in our favor, and we note it. The GPU branch of the ppl evaluation (NVIDIA MX250 under WSL2) gives ppl matching CPU with an accuracy of 10⁻³ (17.067 vs 17.066); the discrepancy of the f32-GPTQ quantization itself — see 5.4.

5.4. Validation of the numbers

Grid fitting, refit, and GPTQ are carried out by a reference numpy implementation (float64). The pipeline's GPU shadow was verified by a separate gate: the discrepancy of weighted layer errors between CPU and GPU quantization ≤ 0.03 %, the ppl discrepancy — 0.006 %; on this basis part of the rows (fp8, the Qwen b4 family) were computed by the shadow front and marked in the tables as "gpu". The full set of artifacts (CSV, JSON, codes) is attached (Section A).

6.3. Form vs rounding

The form and GPTQ compensation add up rather than compete: on b3 the "uniform + κ" configuration (search over only the global table scale) yields 19 285 on Qwen — 3 times better than pure uniform, but 281 times worse than the fitted form under the same GPTQ. Lloyd refit of the table (Alg. 2, 3 rounds) adds on top: SmolLM b3 52.6 → 39.2 ppl (−25.4 %).

And a separate observation on the safety of the fitting itself. The κ range (fit_scale) has been clamped from the very start ([0.40; 1.25]) — yet on SmolLM uniform_k fails at almost every rung: b7 — 44.0; b6 — 55.5 vs 23.7 for pure uniform; b5 — 389; b3 — 29 068; b2 — 45 million (fp32 ladder; base 23.4). The fp16-GPU trace reproduces this (b6 — 90.6; b4 — 1 665). The issue is not the width of the range: in one tensor (layer 11, mlp.down_proj) the Hessian weights in the heavy tail are nearly zero, and the surrogate objective treats truncating the tail as free (κ ≈ 0.66, raw tensor error 0.008 % → 11.8 %), while the model needs the tails. On Qwen uniform_k stays adequate at the top rungs and falls from b4 (159 → 19 285 → 7.5 million). Conclusion: besides range clamping, scale fitting needs a tail guard — a fallback to κ = 1 when the quantiles' weight mass is near zero; without it the method is unpredictable on the rungs where it promises improvement.

Compressing the form description to three coefficients comes cheap: +1.13 % (shared b) or +1.53 % (shared a) at 16 levels, but the full transition to the symmetric 2s form rises to +2.5 % on average and +26 on the worst tensor — the asymmetry of the halves of the weight distribution is real, and different (a, b) pairs catch it. This is also visible on the θ map of all tensors (gridmap): the sign patterns of the deviations (a−1) and (b−1) occupy 3 of the 4 quadrants [SmolLM — [(a, b): 7 / (ā, b): 13 / (ā, b̄): 1]; Qwen — [(a, b): 2 / (ā, b): 19]] — a single "correct form" for all layers does not exist, per-tensor fitting is mandatory.

6.5. Refutation of equal-mass grids

The intuitively attractive idea of "placing levels so that an equal number of weights falls between neighbors" (by analogy — optimality for a uniform objective under a non-uniform density) has been experimentally refuted: the equal-mass grid gives +139 % of error against uniform at 3 bits and +331 % at 4 (Fig. 3; the κ-scale correction — eqmassk — does not save it: +113 %). The reason is that equal masses equalize the number of weights in a bin, while the quadratic weighted objective pays for distance: densifying toward the modal zone without letting the tail steps stretch punishes the heavy tails intolerably. The only "fair" compromise — lloydhess (full weighted Lloyd without parameterization) — beats our formula by units of a percent of the objective, but requires iterations over the whole tensor; the Kumaraswamy formula gives the same result in a single compass descent.

6.6. Fixed "smart" grids: NF4 and FP4 E2M1

At equal storage cost, fixed grids lose to fitting, and the ranking is informative: NF4 (Gaussian quantiles) — better than uniform (−28 % of the objective at 3 bits), but worse than shapeq (−40 %); the hardware FP4 E2M1, with its geometric ladder ±{½, 1, 1½, 2, 3, 4, 6}/6, is denser than NF4 near zero and coarser in the tails — by our hypothesis it should land between uniform and shapeq (the b4 fp4 row in Tables 1–2).

6.7. Outliers vs group scale

The hypothesis "reserve the top code for an outlier with a low-bit correction after linearization" did not hold: scheme D loses to both baselines (~+6 % of the objective vs B) while making the group 0.07–0.09 bit/weight more expensive, and oracle C shows that the ceiling of the whole "channel for the outlier" family lies below current solutions — because saving a level in the table costs more than the accuracy of one weight per group (a 96–128-weight group "buys" outlier accuracy at the price of coarsening the grid for all).

6.9. True 4-bit packing: memory and format accuracy

So that the ppl numbers would not remain "fake quantization in fp32", the b4 shapeq configuration was assembled as a genuine packed file (https://huggingface.co/RomanPokora/shapeq-q4lut-models): 4-bit codes (two per byte), fp16 group scales, a 16×fp16 LUT per tensor. The experiment answers two questions: (1) how much memory the format costs and (2) whether LUT dequantization loses anything beyond the error of quantization itself. The second answer is exact: the ppl of the packed model and of fake-quant (weights snapped to the same grid, computed as fp32) matched to all 14 significant digits (Table 5), i.e. all of the ppl damage comes from the 4 bits, not from the runtime. Speed was not measured here: a correct speed comparison is given only by a mature fused decoder with equal conditions for all methods (including the fixed NF4/IQ4_NL); numbers from a homegrown python prototype would characterize the prototype, not the method. This measurement was taken in the llama.cpp fork with a kernel for our format (https://github.com/stiggigy-jpg/shapeq-q4lut) — see the "q4lut" row in Table 7 (§6.11).

7. Discussion

7.1. Why the shape works: high-rate quantization theory vs. equal mass

The classical quantization asymptotics for the error order r=2 prescribes a level density λ(x) ∝ p(x)1/3 — where p is the data density (Zador's high-resolution quantization result as presented by Gersho [16]). A uniform grid takes λ = const (under-packed at the mode); an equal-mass one — λ ∝ p (exponent 1 instead of 1/3). That is why eqmass is not "nearly optimal" but worse than uniform (Section 6.5): it packs levels at the mode too densely and pays with distances in the tails, and a quadratic objective pays with the square of the distance. The Kumaraswamy family is not, strictly speaking, a family of p1/3-grids, but its two-parameter bends cross the required profile freely — and, unlike the theorem, they work at small L (16 levels is not asymptotics) and with a weighted, not uniform, objective.

7.2. Hessian weighting

The diagonal of the Hessian is the mean squared channel activation; weighting by it tells the grid where an error hurts most: channels through which large signals pass (the well-known source of outlier trouble — LLM.int8 [5]) receive a denser grid. The full matrix H is left out of the fit: off-diagonal crossings are already handled by the GPTQ compensation, and the fit-matrix experiments showed an almost complete agreement of the diag(H) objective with the full quadratic form. The name SHAPEQ denotes the two ingredients of the method: a shape fitted per tensor, and quantization that keeps the existing code and scale machinery.

7.3. Parametrics vs. Lloyd

The non-parametric lloydhess beats the formula by 1–2 % of the objective — and we give up these percents: 4 parameters fitted over 150k points are a hard regularization; they do not overfit calibration noise and give equally predictable behavior on all tensors (full Lloyd on "skinny" groups sometimes drops levels into empty bins). Refit (Alg. 2) is a dosed compromise: 3 rounds of Lloyd over the formula gave −25 % ppl at b3 and almost nothing at b4: the fewer levels, the more polishing is worth it.

7.4. Where this plugs in

The method changes the alphabet, not the pipeline: the decode stays a table lookup (like IQ4_NL [15]), so the cost is equal and the quality is above fixed alphabets. Rotation methods (QuIP [7]) fight the same problem — non-isotropy and tails — by rotating the weight space; this is an orthogonal lever, and the combination "rotation + fitted shape" is the natural next step. There is no competition with hardware FP4/MX [14]: they pay off in the compute-bound W4A4 regime, our method — in the memory-bound weight-only one, where a table of 16 fp16 numbers per tensor costs nothing. Our data also suggest a "shape library" compromise: keep K=8…16 pre-fitted tables per layer type and pick one for the group with a 3-bit pointer — a price of ~0.05 bits/weight instead of 0.0006 bits per tensor, should LUT memory ever become a problem.

7.5. Economic framing

Shape fitting is one-off: <1 s per tensor at quantization time (a full model run — minutes), storage — 32 B per tensor, inference — unchanged. The gain concentrates in the 2–4-bit zone, where the bit hunt happens: at 4 bits this is −4.2 ppl on Qwen (22.6 → 19.2, twice as close to the fp16 loss); at 3 bits it moves a configuration from "model broken" to "model works" (55 703 → 68.5). At 8 bits the shape, as theory predicts, is almost unnecessary — the 8/6-bit ladder (rows in progress) probes the saturation point.

7.6. Plugging into the GSQ / RCO pipeline

The method is designed as a stage of the existing GSQ / RCO quantization pipeline (our GSQ pipeline; in this paper GSQ is represented by its assignment core — GPTQ alternating with table refit, RCO — a Lagrangian 2/3-bit allocation across layers under an exact budget). The integration changes neither the file format nor the decoder: (1) table fitting inserts before assignment as one new stage (fractions of a second per tensor with the compass-descent fit, seconds — with refit; the calibration run for the immatrix/GPTQ is already shared); (2) GSQ assignment works on the fitted grid as on a parameter — the code and masks do not change; (3) for RCO the LUT cost (32 B per tensor) is noise in the budget problem, and layer ranking by proxy error only benefits from a uniform alphabet. The synergy hypothesis: RCO, distributing bits across layers, gets a fairer layer comparison when all layers share one grid methodology; testing it is planned.

7.7. A histogram instead of a subsample

The original fitter (fit_warp, fit_scale, weighted_lloyd) rotated parameters over a random 150k-point subsample, seeded from the tensor hash. This is cheap but introduces result variance and a cost linear in tensor size. The current fitter builds a weighted histogram of group values (8192 bins) once in O(n); each trial then costs O(bins), while the objective is unchanged up to a bin bias of order (bin width)2/12. On real tensors and heavy-tailed synthetic data the histogram grids are no worse (worst deviation +0.01 %, typically 0.5–4 % better), the result is fully deterministic, and fitting is 1.3–16× faster. On the model, SmolLM b4 takes 66 s instead of 1039 s; perplexity changes by −4.9 % on SmolLM b4 (27.047 vs 28.440), −0.8 % on Qwen b6 and +0.8 % on Qwen b4 (the last within the old subsample variance). Three independent implementations (OpenCL, host numpy, VM numpy) agree within 0.40 %. Since 19 November 2026 the histogram path is the default; QB_LEGACY_FIT=1 reproduces the old one, and all numbers measured on it are reported as measured.

7.8. Reproducing RCO: bit allocation over our grid

The RCO method (Helcig and Alistarh, 2026 [17]) allocates bit widths across layers on an exact-budget manifold by optimizing a layered discrete Gumbel-softmax. We reproduced its quantize–search–checkpoint stage on CPU (gloo and a device patch), with 32×2048 calibration tokens and 60 search steps instead of 300. The search took about 22 hours of a single-threaded slot and was limited by the 7.6 GB RAM of the machine.

Allocation. Both learned allocations degenerated to two extreme widths: at a 3.5-bit target, 155 layers at 3 bits and 55 at 5 bits; at 4.0 bits, 104 layers at 3, one at 4 and 105 at 5. At the top of a linear budget the simplex vertex wins, so no intermediate width appears.

Numerical failure in the CPU reproduction. The OBQ stage silently diverged: 4-bit scales were inflated 7.7-fold, the dequantized norm exceeded the weight norm by 1.64×, per-layer NMSE reached 2.07 (worse than a zero approximation), and the search objective started at 10.9 against a fp32 cross-entropy of 3.2. OBQ error feedback scales by chol(H−1) and explodes on a degenerate Hessian; the Hessians are not persistent, so the basis cannot be recovered from the corrupted database. This is not an upstream defect — their GPU pipeline agrees — but a reproduction should check the NMSE of the fake-quant checkpoint before launching the search.

The useful comparison is not their quantizer against ours (broken above), but their bit allocation over our grid and rounding (Table 10, protocol of Table 1, group 96).

7.9. Mass-balance ternary quantization: theory, scan, negative result

Ternary negative result. We also tested whether assigning weights to {−1, 0, +1} with equal masses per level [18] plus a three-value group LUT gives a usable weight-only PTQ at ≈1.9 bits. On all 210 SmolLM layers (group 96, MSE proxy), nearest-level assignment gives NMSE 0.1893; equal thirds 0.2136 (12.9 % worse); the best outer-level share p=0.26 gives 0.1970, and even a per-group oracle over p (0.1916) does not reach nearest level. The optimum p≈0.26 matches the Gaussian level-density law (22–28 % on the outer levels), so equal thirds is optimal only under the Gaussian prior. End-to-end on Qwen2.5-0.5B (fp32, group 128, Table 11) pure ternary loses about three orders of magnitude of perplexity at a weight NMSE of 0.19–0.23, and the arm order repeats the MSE order. Ternary quantization therefore needs training or activation awareness; pure assignment is not enough.

8. Limitations

  • Scope: two small models (0.135B and 0.5B parameters) and one dataset (WikiText-2). Calibration and evaluation use the same corpus, which is standard GPTQ practice but leaves a risk of self-overfitting. Transfer to 7B+ models and to HellaSwag/MMLU-class tasks is not established.
  • The Hessian is stale: it is not rebuilt after quantization. On degraded configurations this works against the method, but the size of the distortion was not measured.
  • Decode speed is not claimed. A fair tokens-per-second comparison needs one mature fused decoder for all methods; a Python prototype would describe the prototype. The llama.cpp fork in Section 6.11 is a reference kernel, not an optimized one: LUT decoding is 2.3× slower than Q4_0 on prefill and 1.9× slower on decode, and closing that gap requires a repack-GEMM path. Only the memory cost of the format is measured (Table 5).
  • The b2 rung shows the monotonicity of the effect; none of the b2 configurations is practically usable.
  • AWQ scaling and sparse corrections (SpQR) were not compared at equal cost; those runs are planned.
  • The legacy fitter used a random 150k subsample, so b4 perplexity varies between runs: SmolLM b4 SHAPEQ was observed in 31.4–38.6 (±10 %). At 3 bits the spread is far smaller than the gap between methods, so the uniform↔SHAPEQ result (×30…×550) is robust, but single b4 numbers should be read as "a few percent to tens of percent", not to the second digit. The histogram fitter (Section 7.7) removes the source: the grid becomes an exact function of the tensor. Numbers from the old path are reported as measured.
  • The RCO reproduction deviates from the original protocol (CPU, 32×2048 calibration, 60 search steps). The OBQ divergence is not localized, so Table 10 compares our grid over their allocation, not their full method. The ternary result uses one model.

9. Conclusions

  1. Grid shape is an independent and cheap quality lever in weight-only quantization. Fitting four parameters per tensor costs 32 B of storage and under a second of CPU time, and yields from −7…−15 % perplexity at 4 bits to orders of magnitude at 3 bits against a uniform grid at equal cost.
  2. The effect reproduces on different architectures and grows as the bit width shrinks; at 8 bits, as the asymptotics predict, it tends to zero.
  3. Equal-mass grids, although intuitively optimal, are 31–331 % worse than uniform ones. The result is consistent with over-concentration relative to Zador's p1/3 level-density law.
  4. Fixed smart grids (NF4, FP4 E2M1) lose to per-tensor fitting: one shape for all tensors carries a constant quality tax.
  5. Shape and GPTQ compensation add up; Lloyd refit amplifies the shape at low bit widths.
  6. The fitted shape justifies the LUT decode: dropping the table in favor of "scale only" at 4 bits costs ×8…×13 perplexity, and at 3 bits the model is not saved at all (×553). The compromise with a group shift (Q4_1-style) costs +17…+30 % perplexity (Section 6.14).
  7. The method is a ready-made stage of a GSQ/RCO pipeline: table fitting before assignment, with no change to the file format or the decoder. With RCO's per-bit allocation the gain does not add up (Section 7.8).
  8. The method is deterministic, needs no training, and changes only the quantization alphabet, so it composes with existing quantizers. The next steps are validation on 7B+ models and broader benchmarks, comparison with AWQ and sparse corrections, and an optimized LUT kernel with a repack-GEMM path.

Appendix A. Reproducibility

Reference implementation: Python 3 with numpy float64 on CPU; GPTQ and Hessian caching also run in float64. The grid fitter, the packing script, the evaluation drivers, and all raw CSV/JSON artifacts are in https://github.com/stiggigy-jpg/shapeq-paper. The Q4_LUT/Q4_LUT64 kernels are at https://github.com/stiggigy-jpg/shapeq-q4lut; the packed GGUFs and fitted packs are at https://huggingface.co/RomanPokora/shapeq-q4lut-models, with hashes in SHA256SUMS.txt. The SmolLM pack uses the legacy engine; the Qwen pack uses the histogram engine. A rerun is gated by those hashes and by the perplexity and greedy-64 anchors in b4_qwen_shapeq.pt.json.

python fit_b4.py --model HuggingFaceTB/SmolLM-135M --engine legacy --test-chunks 96 \\
    --out b4_smollm_shapeq.pt
python fit_b4.py --model Qwen/Qwen2.5-0.5B --dtype fp16 --group 64 --test-chunks 16 \\
    --out b4_qwen_shapeq.pt
python pack_q4lut.py --pack b4_smollm_shapeq.pt \\
    --base smollm-f16.gguf --out smollm-135m-q4lut.gguf
python run_ppl_grid.py --model HuggingFaceTB/SmolLM-135M --engine legacy \\
    --out results_ppl.csv

Environment used for the reported numbers: WSL2, Linux kernel 5.15, 12 CPU cores, 7.6 GB RAM, 2 GB swap; NVIDIA MX250 2 GB (CUDA 11.8, torch 2.4.1+cu118) for GPU perplexity only. The GPU perplexity evaluation was cross-checked against CPU (17.067 vs 17.066). The GPU quantization gate required weighted layer-error divergence ≤ 0.03 %. Absolute perplexity can shift in the last decimal or two with BLAS reduction order.

Artifacts: results_ppl.csv, results_ppl_qwen.csv, results_layers.csv, the probe JSON files, the ternary scans, and the RCO search configurations. results/MANIFEST.md maps each file to a table and a regeneration command.
